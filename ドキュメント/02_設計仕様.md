# 02_設計仕様

01_要件定義.md を踏まえた技術設計。実装は「実装」フォルダ配下に作成する。

## 1. 全体アーキテクチャ

- **完全フロントエンド構成**。サーバー・API・ビルドステップなし。GitHub Pages にリポジトリをそのまま公開する。
- フレームワーク・バンドラーは使用しない（既存プロジェクト群の方針を踏襲）。Vanilla HTML / CSS / JavaScript（ES Modules）のみ。
- 外部ライブラリへの依存も持たない。推移グラフは軽量な自前SVG描画で実装する（CDN依存やビルドを避け、オフライン読込の可搬性を優先）。
- データ永続化は **IndexedDB** を採用する（localStorageは文字列のみ・容量小のため、構造化データ＋容量面でIndexedDBが適切。01要件の「localStorage/IndexedDB」のうちIndexedDBを採用し、以降はこちらに統一する）。
- 画面遷移はページ遷移（別HTML）を行わない **SPA構成**。`js/app.js` が画面（view）切り替えを担当する、`勉強/study` プロジェクトと同じ構成パターンを踏襲する。

## 3. データモデル（IndexedDB）

DB名: `kurekaSplitDB` / バージョン: `1`

### 3.1 `transactions`（明細）

| フィールド | 型 | 説明 |
|---|---|---|
| id | number（自動採番） | 主キー |
| date | string (`YYYY-MM-DD`) | 利用日 |
| yearMonth | string (`YYYY-MM`) | 集計・グループ化用（dateから算出、index対象） |
| cardType | `'SMC' \| 'AMEX'` | カード種別 |
| cardHolderName | string | カード会員名（参考情報。SMCはブロック見出しから、AMEXは行ごとの列から取得） |
| description | string | 項目名（三井住友=利用先／AMEX=ご利用内容） |
| amount | number | 金額（円） |
| category | `'A' \| 'B' \| 'BOTH' \| null` | 振り分け区分。未振り分けは `null` |
| isAuto | boolean | 自動振り分けによる確定かどうか |
| matchedRuleId | number \| null | 自動振り分けで一致したルールID（手動修正後もマッチ履歴として保持） |
| importId | number | 取込バッチID（`importLogs.id` を参照） |
| createdAt | string (ISO) | 取込日時 |

index: `yearMonth`, `category`, `importId`

### 3.2 `importLogs`（取込履歴・重複防止用）

| フィールド | 型 | 説明 |
|---|---|---|
| id | number（自動採番） | 主キー |
| cardType | `'SMC' \| 'AMEX'` | カード種別 |
| targetYearMonth | string (`YYYY-MM`) | 対象年月（取込時にユーザーが確認・確定した値。3.3節参照） |
| fileName | string | 取込したファイル名（参考表示用） |
| recordCount | number | 取込明細件数 |
| importedAt | string (ISO) | 取込日時 |

index: `cardType_targetYearMonth`（複合、重複判定に使用）

### 3.3 `rules`（自動振り分けルール）

| フィールド | 型 | 説明 |
|---|---|---|
| id | number（自動採番） | 主キー |
| keyword | string | 項目名に対する部分一致キーワード |
| category | `'A' \| 'B' \| 'BOTH'` | 一致時の振り分け先 |
| priority | number | 数値が小さいほど優先。画面上の並び順＝優先順位（上にあるルールほど優先） |
| enabled | boolean | 一時的にルールを無効化するためのフラグ |
| createdAt | string (ISO) | 作成日時 |

マッチングは **大文字小文字・全角半角を区別しない部分一致**で行い、`priority` 昇順に評価して最初に一致したルールを採用する（早勝ち方式）。同率の場合は `id` の若い順。

### 3.4 `settings`（単純なキー・バリューストア）

| キー | 用途 |
|---|---|
| `lastBackupAt` | 最終エクスポート日時（バックアップ促進表示に使用） |

## 4. CSV取込・パース仕様

### 4.1 文字コード変換

- `<input type="file">` で取得した `File` を `ArrayBuffer` として読み込み、`new TextDecoder('shift_jis').decode(buffer)` でデコードする（主要ブラウザはこのラベルを標準サポート）。

### 4.2 CSV行パース

- 単純な `split(',')` は使わず、ダブルクォート内のカンマを考慮する簡易CSVパーサ（状態機械／正規表現）を共通関数として実装する（AMEX形式の `"DOMINO'S PIZZA JAPAN, INC."` のようなケースに対応するため）。

### 4.3 形式判定

1. 1行目をパースし、列が `ご利用日,データ処理日,ご利用内容,カード会員様名,会員番号 #,金額,...` に一致 → **AMEX形式**
2. 1行目が3列で、1列目が「様」を含み、2列目がカード番号らしきパターン（数字とハイフン・アスタリスクのみ）→ **三井住友形式**
3. どちらにも一致しない場合はエラーメッセージを表示し、取込を中断する。

### 4.4 明細抽出

**AMEX形式**
- 2行目以降を1明細として処理。
- `date` = 列0（ご利用日）、`description` = 列2、`cardHolderName` = 列3、`amount` = 列5（カンマ除去して数値化）。
- 金額列が空、または `description` が空の行はスキップ（合計行等の想定なし。念のためガードのみ）。

**三井住友形式**
- 1行ずつ走査し、「様」を含む3列の行が来るたびに、以降の明細行に適用する `cardHolderName` を更新（該当行自体は明細として取り込まない）。
- 明細行（先頭列が `YYYY/MM/DD` 形式）: `date` = 列0、`description` = 列1、`amount` = 列2（数値化）。
- 先頭列が日付形式でない行（末尾の合計行など）はスキップ。

### 4.5 対象年月の確認

- カード種別の判定をファイル内容に基づいて行う方針のため、**対象年月（`targetYearMonth`）もファイル名に依存せず、取込画面でユーザーに確認・確定させる**。
- デフォルト値は「取込明細の `date` の中で最も件数の多い年月」を自動算出して提示し、ユーザーが必要に応じて変更できるプルダウンとする。
- 確定した `targetYearMonth` と `cardType` の組み合わせが `importLogs` に既存であれば、上書き確認ダイアログを表示する（「再取込すると同一年月・同一カード種別の既存データを置き換えます」）。承認時は該当 `importId` に紐づく既存 `transactions` を削除してから再登録する。

### 4.6 取込フロー全体

1. ファイル選択 → デコード・形式判定
2. 明細抽出 → 対象年月確認画面を表示（デフォルト値提示）
3. ユーザーが対象年月を確定 → 重複チェック（4.5節）
4. `importLogs` に1件登録、`transactions` に明細を登録（`category=null`, `isAuto=false` で仮登録）
5. 自動振り分けルール（5節）を全件に適用し、一致したものを確定
6. 結果サマリ画面を表示（自動振り分け件数／未振り分け件数）

## 5. 自動振り分けロジック

```
function applyRules(transaction, rules):
  for rule in rules.filter(r => r.enabled).sort(by priority asc):
    if normalize(transaction.description).includes(normalize(rule.keyword)):
      return { category: rule.category, matchedRuleId: rule.id, isAuto: true }
  return { category: null, matchedRuleId: null, isAuto: false }
```

- `normalize()` は小文字化＋全角英数記号を半角化する簡易正規化関数（`autoRules.js` に実装）。
- ルール適用は「取込直後」に加え、「ルール管理画面でルールを追加・編集した際、未振り分け明細に対して再適用（任意実行ボタン）」でも呼び出せるようにする（既存の未振り分けを一括で自動振り分けし直したいケースに対応）。
- 既に手動で振り分け済み（`isAuto=false` かつ `category` 設定済み）の明細には自動適用を行わない（上書きしない）。

## 6. 画面構成・遷移

下部ナビゲーション（5タブ、スマホ幅を想定した固定フッター）で切り替えるSPA構成。

| タブ | view id | 内容 |
|---|---|---|
| 取込 | `import` | CSVファイル選択・取込フロー（4.6節） |
| 振り分け | `assign` | 未振り分け明細の操作画面（メイン画面） |
| 履歴 | `history` | 振り分け済み一覧（月ごとグループ） |
| 集計 | `report` | 最新月ハイライト・推移グラフ・月別ドリルダウン |
| 設定 | `settings` | ルール管理・データエクスポート/インポート・全削除 |

初回起動時（`transactions` が0件）は自動的に「取込」タブを表示する。

### 6.1 振り分け画面（`assign`）

- 未振り分け明細を `yearMonth` 降順→同月内は `date` 降順で、**月ごとに見出し付きグループ表示**。
- 各明細行に「Aの支払い」「Bの支払い」「二人で支払い」の3ボタンを表示（ボタン最小タップ領域 44px以上、フォントサイズを本文比+2段階程度拡大）。
- 一覧内で1件を「フォーカス中の明細」として管理し、以下のキーボード操作を割り当てる（`keyboardNav.js` で共通化）。
  - `←` : Aの支払い を選択
  - `→` : 二人で支払い を選択
  - `↓` : Bの支払い を選択（要件の←/→に加え、3択を全てキーボードから選べるように補完。タッチ操作のみの場合は影響しない）
  - 選択後は自動的に次の未振り分け明細へフォーカスを移動する。
- 各行の利用日は `YYYY/MM/DD（曜）` 形式で年を省略せず表示する。

### 6.2 履歴画面（`history`）

- 振り分け済み明細を月ごとにグループ表示（表示仕様は6.1と同様）。
- 各行に区分（A/B/共同）と、自動振り分けの場合は「自動」バッジを表示。
- 行タップで区分変更用の3択を再表示し、修正できる（修正時は `isAuto=false` に更新し、手動確定として扱う）。

### 6.3 集計画面（`report`）

- 上部: **最新月ハイライトカード**（3グループ: 「二人の合計／一人当たり」「Aの合計」「Bの合計」を大きな数字で表示）。
- 中部: 「二人の合計」の月次推移グラフ（自前SVG折れ線、直近12ヶ月をデフォルト表示範囲とする）。
- 下部: 月一覧（月・二人合計・A合計・B合計を並べたテーブル）。行を選択すると、その月の振り分け済み明細一覧をモーダルまたは `history` 画面へ遷移して絞り込み表示する。
- 最下部: CSVダウンロードボタンを2種類配置する。
  1. 月別集計CSV（年月・二人の合計・一人当たり・Aの合計・Bの合計）
  2. 振り分け済み明細CSV（年月・利用日・項目名・金額・区分・カード種別・カード会員名・自動振り分けの別）
  - 生成は `csvExport.js` の共通関数（値のCSVエスケープ、UTF-8 BOM付きでのダウンロード）を利用する。

### 6.4 設定画面（`settings`）

- **ルール管理**: ルール一覧（キーワード・区分・有効/無効・並び替え用の上下ボタン）、追加フォーム、削除。
- **データ管理**: 全データをJSONとしてエクスポート（ダウンロード）／JSONファイルからインポート（復元・上書き確認あり）／全データ削除（確認ダイアログ必須）。

## 7. エクスポート/インポート仕様（JSON）

```json
{
  "version": 1,
  "exportedAt": "2026-08-09T12:00:00+09:00",
  "transactions": [ /* transactionsストアの全レコード */ ],
  "importLogs": [ /* importLogsストアの全レコード */ ],
  "rules": [ /* rulesストアの全レコード */ ]
}
```

- インポート時は `version` を検証し、非対応バージョンの場合はエラー表示。
- インポートは「全置換」を基本動作とする（既存データとのマージは行わない。バックアップからの復元用途のため）。

## 8. 非機能要件対応

- 対応ブラウザ: iOS Safari最新、Android Chrome最新、PCはChrome/Edge最新2バージョン。IE非対応。
- レイアウトはCSS Flexbox/Gridによるレスポンシブ対応とし、スマホ縦画面幅（375px〜）を基準に設計する。
- オフライン動作（Service Worker等によるキャッシュ）は本バージョンのスコープ外とする（GitHub Pagesへの初回アクセスにはネットワークが必要）。
